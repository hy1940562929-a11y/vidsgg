# 078：短关系区间读出实验结果

2026-10-15。真实训练完成、结果已导入、独立复算通过。**结论：这一版没有改善短关系，不扩大训练。**

## 1. 这次验证了什么

尝试把“逐时间点判断关系是否成立”补充为“直接给起点—终点组成的区间打分”。比较联合起止建模与独立边界打分；再比较同一实体对上正确区间和邻近区间的训练，是否有额外帮助。

固定输入轨迹、实体对、编码器、query、谓词分数、候选数量和排序，只训练时间读出部分，改变预测区间并裁取同一条proposal的框。推理不使用GT选择短关系、实体对或区间。GT只用于训练监督和预测封存后的评估。

这是受区间抽取方法启发的原型，不是TriDet、GlobalPointer或DiFiNet的完整复现。没有实现质量重排序，没有重训编码器。每个query读取冻结特征与类别概率；该query下的不同谓词候选共享新区间，尚不是每个谓词单独预测区间。

| 方案 | 改动 |
|---|---|
| baseline | 原VrdONE输出 |
| mask | 继续训练原mask投影头 |
| independent | 起点和终点分别打分 |
| joint | 增加起点与终点之间的低秩交互，参数量与independent一致 |
| joint_hard | joint加上同实体对、同谓词的邻近区间比较训练 |
| joint_random | joint加上长度、数量配对的随机位置区间比较训练 |

span方案均为21,747参数，500步、seed78、相同batch顺序，AdamW lr=3e-4。mask为197,376参数、lr=1e-5，使用原focal+dice目标，是实用对照而非等参数架构对照。全部只评估最后一步，没有按验证集挑checkpoint。

span方案从相同的零残差输出开始，共享原mask外包区间的距离先验。合法采样区间起点小于终点，stride=4，最小5帧；映射为`[origin+4*first, origin+4*last+1)`。训练附近区间包括扩张、截断、平移，按同pair/predicate全部保留标注的最大IoU计算质量；被截断的标注不进入辅助监督。hard/random只匹配长度和数量，没有匹配IoU差距或损失激活程度。

## 4. 为什么下降：这版读出主要把区间拉长了

128视频前100候选共12,800个槽位：

| 方案 | 区间改变 | 变长 | 变短 | 等长平移 |
|---|---:|---:|---:|---:|
| mask | 1,649 | 466 | 1,175 | 8 |
| independent | 1,685 | 1,400 | 281 | 4 |
| joint | 1,630 | 1,405 | 222 | 3 |
| joint_hard | 1,624 | 1,410 | 211 | 3 |
| joint_random | 1,627 | 1,404 | 220 | 3 |

joint改变的1,630条中，1,391条纯外扩、220条纯内缩、19条同时移动和改变宽度；长度变化中位数+28帧。这些是候选槽位，同一pair/query的不同谓词可能重复，不能当成独立事件数。

具体例子：`1102_5804131706/GT54`，`adult—towards→adult`。实体连续共存10.077秒，关系持续2.603秒。

| 项目 | 原模型 | joint |
|---|---|---|
| GT区间 | `[251,329)` | 相同 |
| 预测区间 | `[249,342)` | `[249,402)` |
| 候选排名 | 13 | 13 |
| 分类分数 | 0.9383035898 | 相同 |
| 主体vIoU | 0.661744 | 0.366808 |
| 客体vIoU | 0.702793 | 0.451135 |

终点延后60帧，把本来正确的预测变成错误。即使新的纯时间IoU仍约0.5098，主客体vIoU已低于0.5。本次区间外扩直接破坏匹配；分类分数没变。这不能证明原VrdONE全部失败都来自同一原因。

新增4条来自`1007_3557498300/GT6`、`1110_4372494989/GT113`、同视频GT114、`0083_6879924118/GT7`，分别是3.637秒watch、4.137秒away、4.137秒away、9.009秒watch。全部通过扩张改善原来偏窄的区间。15条损失的原匹配候选也都被扩张。

另一损失`1011_3376544720/GT0`仍可被第133名匹配：原高位候选因区间变化失效，Top100丢失而Top200尚存。顺序没变，不能说模型降低了分类置信度。

## 5. 训练损失下降，却没有带来目标命中提升

固定匹配query诊断，含全部563/169条：训练tIoU≥0.5命中458/563→447/563（新增1、损失12），短关系138/200→129/200（新增0、损失9）；开发121/169→120/169，短关系24/44→23/44。这是采样区间tIoU，不是官方检测召回。

**本轮共同CE下降，但训练和开发的tIoU≥0.5命中数均下降，最终检测也未改善。**不能简单解释为只在验证集泛化失败，也不能说所有定位指标都退化：训练精确端点命中215→227，开发54→55。尚不能确定是损失形式、先验残差参数化、训练分布或冻结表征中的哪项造成。

追加核验读取已有checkpoint，2.94秒，无训练。这是结果出来后的诊断，不是预注册机制验证。

## 6. 结论与下一步边界

- **Intervention：**此版joint未优于independent，hard未优于joint/random；总体和短关系均退化。
- **Observation / Diagnosis：**预测以外扩为主；13条短关系损失均伴随原匹配候选扩张；同缓存CE下降但门槛命中下降。
- **Hypothesis，未验证：**更贴近区间重合质量的监督，或有证据约束的局部边界修正，可能改善当前失配。不能据此断言特定IoU损失或局部头必然有效。
- **不支持：**历史信息压制短事件的因果机制、所有联合边界方法无效、冻结特征没有时间信息、完整benchmark获得提升。

按启动前协议和读结果前补充门槛，判定**DO_NOT_EXPAND_THIS_VERSION**。Reviewer认为结果可信、需保留范围限制。没有放弃短关系研究主方向，也没有合并试验代码为主方法。

下一项最小试验应先在训练/开发缓存检验“损失改善是否同步改善区间IoU与短关系命中”，同时报告原正确区间损失；通过后才重新评估128视频。不能用验证GT选择是否收紧，不直接增大模型与训练时长。该后续设想未执行。
