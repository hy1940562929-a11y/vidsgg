# 短关系为什么丢失：可干预原因诊断包079

2026-10-19。状态：准备代码，尚未执行真实实验。服务器连接后使用已有PyTorch环境；不安装依赖，不覆盖旧实验。

## 这次要得到什么

找出“改哪个计算环节，短关系的正确时间输出就会增加”。不先决定加傅立叶分支、CNN或记忆模块。每项干预都保留长关系对照，报告新增、损失和净变化。

| 要找的原因 | 通俗解释 | 本轮实验 | 什么结果值得继续 |
|---|---|---|---|
| 看得太稀 | 关键变化发生在两个采样点之间 | A：每4帧取一次→每2帧取一次；与只插值、不增加真实观测对照 | 真加密优于插值，并稳定增加短事件时间命中 |
| 粗尺度融合不合适 | 大时间范围的特征进入精细特征后，短变化更难被利用 | A：冻结权重，只将最细层的粗尺度注入强度从1改为0.5或0 | 两种削弱都呈改善，且没有不可接受的长关系损失 |
| 信息进入了模型，但更难读出来 | 融合前能判断的边界，融合后同样的小读出器判断不好 | B：细尺度特征、融合后特征、纯位置输入，使用同容量读出器 | 细尺度优于融合后、且超过位置对照；结合A判断架构路径 |
| 学习目标和实际命中不一致 | loss下降，但预测区间仍过长、错位 | C：相同区间头、初始化和训练顺序，CE对比CE+区间IoU风险 | 短事件实际命中超过CE及初始锚点，长组和总体保持 |

其他原因也列入[完整协议](PROTOCOL.md)：画面不足、标注歧义、指标敏感性、检测跟踪、候选配对、query分配、谓词、数据长尾、解码和排序。本包重点执行上面四个对照；没有把其余原因宣布为已排除。

## 数据与含义

- A复用原27视频正确实体输入，保留实体完整连续共存区间。目标是隔离时间建模，输出为时间候选覆盖，不是正式检测召回。
- B/C复用32个训练来源视频和8个开发视频，原缓存分别保留563/169条关系。B按完整标注重建逐时间点标签，排除被裁剪的实体对并记录分母；实际可用量由审计输出，不能提前假定563/169全部可用。
- 原模型预训练可能见过开发视频，因此这一轮是机制小试。这里不宣称独立泛化，不自动跑全量benchmark。
- 对标注之外的时间，只使用“未标注为该关系”的含义，不将它当作人工确认的真实off。B不用于证明长关系语义压制。
- 本轮没有新实测收益。“预期”是判别模式，不是希望填入论文的性能数字。

```bash
cd /root/autodl-tmp/VrdONE-data/commander_mechanisms_079/code_v1
VRD_PYTHON=/root/miniconda3/envs/rebinding/bin/python
bash run_all.sh "$VRD_PYTHON" config.json ../results_v1
```

以上解释器路径沿用历史环境，连接后以实际已有解释器为准；不存在时会直接报错，不自行安装。`results_v1`必须不存在。中断后换新输出目录，保留原日志。

入口先检查包内哈希、原模型/源码/缓存指纹、依赖与指定CUDA设备，再运行合成测试。之后串行A→B→C。技术失败停止；科学负结果仍被正常保存。模型前向的一致性检查在各阶段内完成。

## 资源与输出

- 只用配置中的单张GPU；不自动抢卡，不启动多进程模型任务。
