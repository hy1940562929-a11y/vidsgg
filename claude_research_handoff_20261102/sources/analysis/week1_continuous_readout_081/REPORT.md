2026-10-19。080之后的探索；沿用原query和原预测，不训练、不重新推理。协议及软件在本轮统计前冻结。

## 2. 固定读出与候选存在性的互斥分解

**读出口径补充（核验077实现）**：固定selected是在同identity的候选中按目标谓词类别分数选出的query，不按当前GT时间挑选；本表只评它的时间形状。oracle是在该identity的全部连续段、全部query中，用GT时间取得最大tIoU，未要求该query正确预测目标谓词/class。因而oracle-only只表示“存在具有时间形状匹配的查询”，同时受GT时间oracle、类别未知、可能更换连续实体段三重限制；不能理解为选一个query即可恢复完整关系，更不是正式R@K。源码：`analysis/research_question_077/boundary_audit.py:316–327`。

|范围|GT数|固定selected时间命中|仅oracle有匹配时间形状|两者均无匹配时间形状|
|---|---:|---:|---:|---:|
|GT27全部|2,573|758/2,573 = 29.46%|973/2,573 = 37.82%|842/2,573 = 32.72%|
|其中所选实体段覆盖GT|1,654|758/1,654 = 45.83%|242/1,654 = 14.63%|654/1,654 = 39.54%|
|短关系<3秒|966|127/966 = 13.15%|346/966 = 35.82%|493/966 = 51.04%|
|短关系且所选段覆盖GT|569|127/569 = 22.32%|64/569 = 11.25%|378/569 = 66.43%|

全体oracle-only的731/973 = 75.13%来自所选实体段不覆盖GT；短关系oracle-only中这一比例为282/346 = 81.50%。这是覆盖属性的分解，不是修改选段后实测恢复数。

当选中实体段已经覆盖GT时，亚秒组187条仅有selected=10/187、oracle-only=1/187、neither=176/187。这个细分里，任意查询中新增具有匹配时间形状的候选很少；不能据此计算完整关系恢复数。选段覆盖和时间候选缺失必须分开研究。
