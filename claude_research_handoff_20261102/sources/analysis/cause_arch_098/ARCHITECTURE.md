# M098草案：联合分配时间证据，再解码事件集合

日期：2026-10-20。**DESIGN_ONLY / UNVERIFIED / NOVELTY_UNCERTAIN**。
对应[唯一原因H098](CAUSE_STATEMENT.md)和[唯一验证E098](EXPERIMENT_CONTRACT.md)。不采纳为正式方法；不复活M091几何监督，不原样重跑M097。

## 1. 为什么考虑改变读取架构

已证事实是“现有query的时间分数难形成短区间”，不是“注意力分配已经被证明有错”。原生VrdONE已有9个事件query和Hungarian逐事件监督。现在提出的改变是：**从每个query独自决定读哪里，改成所有query共同分配有限的时间读取资源。**

只有E098证明这种分配确有可修复的作用，才能将它作为原因对应的架构。E097的149/334容量墙来自旧F等诊断约束，不能拿来证明原生9-query架构天然容量不足。

## 2. 一条完整数据通路

```text
固定实体轨迹与类别
        ↓
原实体对编码器（保持不变）
        ├── 时间特征 f(t) ───────────────────────────┐
        ↓                                         │
9个原有事件query + 时间key/value                    │
        ↓                                         │
联合时间读取算子                                  │
各query读取总量不变；全部query合计覆盖有效时间         │
        ↓                                         │
更新后的9个事件状态 h(q)                            │
        ├── 原分类头 → 每query的谓词/背景概率         │
        └── 原mask embedding → 与 f(t) 点积 ←───────┘
                                 ↓
                           9条时间分数
                                 ↓
                     同一H阈值/min5 → 至多9个区间
```

原逐事件Hungarian、类别监督和mask监督仍在。没有新边界head、新比较器或额外时间几何损失。

唯一核心改变是cross-attention归一化：保持`QKᵀ`和value计算，原row-softmax改成固定边际的联合平衡。每个query行和1；所有query在时间单元t上的合计权重为`9×单元时长/连续段时长`。它使读取不集中丢掉某些时段，但**不会强迫不同query完全互斥**，也不会保证每个事件恰好对应一个query。

解释各部分的作用：

- 固定编码器保留相同视觉与轨迹证据，防止把输入变好算成新机制收益。
- 联合读取直接操纵假设中的证据分配，而非在错误mask产生后统一收紧边界。
- 原事件状态、分类头与mask头共同检验重新读取是否转化成更可分的类别加权集合时间分数和正确区间；该分数不能单独归因于原始mask改善。若下游门槛不通过，原因配方停止。
- 固定9-slot解码与一对一评价限制输出机会，避免多生成候选带来的伪改善。

均匀时间读取也可能有害：背景长时段会消耗预算；多个同时发生的关系可能需要反复读取同一时段；原query self-attention已经可能帮助分工。本设计必须允许这些反例否决，不预设平衡一定优于稀疏关注。

## 4. 新颖性判决与可能成立的贡献

**当前新颖性风险HIGH；不能声称已获得颠覆性新算法。** 从独立读取改为联合分配是架构核心算子的变化，但算子、竞争式slots和时间覆盖均已有先例。

如果唯一实验通过，最多有以下待形成的贡献：

1. 在长共存短关系的明确条件群体中，证明一种跨query证据分配的可操纵贡献，并保留已否决的几何配方和诊断容量限制。
2. 在相同事件预算下，把该因素的修复落实到事件表征与区间输出，展示类别加权集合时间分数、短事件恢复和长事件保护的共同变化。

是否足够成为正式方法，还取决于相对Sinkformers、Slot Attention、TE-TAD、E²DVC的具体区别、完整benchmark和独立数据验证；这些本轮不运行、不自动排队。单纯把Sinkhorn接入VrdONE、mAP略涨，不能交付用户要求的“完整原因＋有依据的创新架构”。

## 5. 唯一最小验证与停止

只执行合同中的N/J同预算对照及同checkpoint撤回/恢复：先验收材料和新9槽容量，确认原低读取现象；再看读取平衡能否同时改善类别加权集合时间分数的局部可分性、时间与类别一致命中，并修复多数**可达缺口**且保护长组。

若平衡实现但下游结果未达到门槛，就拒绝H098及当前架构配方；不追加gate、局部窗口、动态query数、损失或后处理。**本文件只有条件性架构草稿，没有实验结果；三文件交付后停止。**
