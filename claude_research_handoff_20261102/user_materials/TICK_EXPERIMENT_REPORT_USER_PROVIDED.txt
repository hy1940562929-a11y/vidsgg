一句话结论
时间定位有效，但公平协议下整体增益站不住。
带泄漏评测里 A5 的 router 短关系 +8.75pp。换成训练评测不重叠、并要求谓词对上之后，K=9 下短关系是 -1.69pp，长关系掉 5.81pp。真正稳定有效的只有一点：Event 不用 mask-hull，改用 onset 峰值加中位时长，过延展率（OER）从约 0.96 降到约 0.39。

这一阶段有两个问题，后来都得到证实。
一是训练在 val_select 80% 的视频上微调，评测在同样 250 个视频上，存在泄漏。二是 Event 的候选数量远多于 q，匹配只看时间，所以召回被抬高。因此这个 +8.75pp 不能当作论文主结果。

阶段 5：E1 谓词竞争
1
假设
A5 的 Event 热图是各类独立的 sigmoid，类与类之间没有竞争，所以谓词学不对。
2
改动
热图只保留 24 个 Event 类；保留 onset focal 损失负责「何时」；在每个 Event 真值起点帧加 24 类 softmax 交叉熵（权重 1.0）负责「哪一类」；Event 窗口过采样 4 倍并按类别均衡。
3
协议
干净协议，5 个 seed，N 与 E1 配对。

阶段 6：E2 统一排序
针对长关系掉点。做法：不改训练，在解码端把 q 分支和 Event 分支的分数各自按排名校准到同一尺度，合并后做一次跨类型 NMS（IoU 0.5），再取固定 K。新增读出为 router_uni 和 router_cal（不做 NMS 的对照）。

E2 拒绝：统一排序把长关系掉点从 6pp 放大到约 12.7pp。
原因是按排名校准会让两个分支的第 1 名、第 2 名交替排在一起，Event 分支在 K=9 里拿到接近一半的槽位，而 Event 分支的谓词几乎全错。用谓词匹配判断时，短关系和长关系都比未校准更差。这说明槽位竞争的根源不是分数尺度，而是 Event 候选本身的谓词不可信。
阶段 7：E3 时间重锚定
思路：谓词和主客体仍由 q 分支给出，只用 Event 起点峰去重新锚定 q 候选的时间区间，避开 Event 分支谓词不可信的问题。新增读出 ra_same、ra_any 及其 _drop 变体。干净协议，5 个 seed 与 N 配对，结果于 10/23 12:48 PM EDT 出齐。

E3 拒绝：重锚定对短关系完全无增益。
ra_* 四种变体结果几乎一致，短关系贴着 0，长关系反而掉约 1.1–1.6pp，候选数还少了约 13%。_drop 变体只丢了极少候选，没有实际差别。说明 q 分支本身就没有对上这些短关系的谓词和主客体，只挪时间救不回来。K18 时间匹配下 router_med +8.59pp 的「通过」来自约 1.9 倍候选，谓词匹配下为 +0.07pp。
阶段 8：Oracle 区间谓词探针
在真值区间上池化主体/客体 ROI 特征（mean），再加主体/客体类别嵌入，训练 24 类 Event 分类器；对照是仅用 P(谓词|主体,客体) 的先验。训练 Event 真值 207 条（22/24 类），验证 734 条。不改 VrdONE，几分钟即可完成。

| 模型              | top-1 | top-5 |
| --------------- | ----: | ----: |
| 先验 P(谓词\|主体,客体) | 13.1% | 39.5% |
| MLP（特征 + 类别）    | 18.0% | 59.7% |
| MLP（仅特征）        | 17.3% | 50.5% |
| MLP（仅类别）        | 10.9% | 33.7% |
| LogReg（仅特征）     | 14.7% | 50.5% |

Gate 1：15–30% 区间，有信号但不够强。
最好的 top-1 是 18.0%，比先验高 4.9pp；top-5 到 59.7%。说明在真值区间上特征能提供一点类别信息，但远不够单独支撑 24 类。下一步应：扩大 Event 训练数据（1k/全部 train）、合并超类，并做两阶段谓词头（冻结 onset，在预测区间上池化再分类）。不要再调 router 或排序。
