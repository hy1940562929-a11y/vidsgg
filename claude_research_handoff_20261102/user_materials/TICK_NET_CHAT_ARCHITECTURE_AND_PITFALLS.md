# TICK-Net六模块：历史聊天方案及需纠正之处

本文件是本次对历史聊天的整理，不是模型训练结果。原用户报告见同目录TICK_EXPERIMENT_REPORT_USER_PROVIDED.txt；两者不能自动认作同一实现版本。

## 曾提出的完整数据流

```text
主体/客体RoI F_s,F_o + 绝对/相对框几何 + 可选相邻帧差分
  → BSA+主客体时空交互 → e_so[T,C]
     ├→ 多尺度下采样 → 全局语义 z_s[C]
     │                  └→ FPN/跳连上采样 → z_mask[T,C]
     └→ CRM：LN(e_so − broadcast(MLP(z_s))) → z_fast[T,C]
状态query → D_state → z_state[N_s,C]
事件query（峰初始化）→ D_event局部attention → z_event[N_e,C]
状态/事件MCG交叉门控
  ├→ 状态类别 + 动态mask，Tversky/focal/分类监督
  └→ 事件onset热图 + duration预测 → 峰值/带宽区间
统一候选排序与固定预算输出
```

历史目标：持续状态可维持整段，短事件从微弱局部变化中形成紧凑区间，语义共享避免小样本事件头崩溃。

## 不能继承成事实的推断

1. 一阶视觉差分是变化量，不是“加速度”；短关系可能是无明显运动的watch/next_to，并非都表现为高频冲激。
2. 全局平均语义包含事件、身份和上下文，不能自动解释成纯共存背景。相减不保证语义解耦，正交分解也可能删掉目标信息。
3. LayerNorm通常沿通道归一化，不会自动过滤时间恒定成分；“恒定维度方差接近0所以被LN抑制”的论证不成立。
4. 若D_state只cross-attend一个全局向量，softmax只有一个key时恒为1，时间选择能力消失；状态流若要细边界，必须保留有时间结构的证据源。
5. z_event[N_e,C]经过卷积不能凭空产生[T,24]热图，必须明确query与时间特征交互、上采样/投影的真实计算。
6. 213条Event来自某个180视频训练子集，不是整个VidOR训练集只有213条Event；不能把数据抽样造成的稀疏写成数据集总量事实。
7. 事件数归一化不保证各事件梯度范数相等；原focal/Dice也不能只凭“900帧vs9帧”判长事件梯度必定大100倍，需实际计算。
8. 固定峰+中位时长不是严格的时间点过程模型；声称点过程需定义条件强度/事件概率和相应似然。峰值解码不等于连续时间亚帧信息。
9. Tversky中FP/FN权重约定应与代码一致；加大FP罚只能提供偏好，不保证长关系不掉或所有mask都紧凑。
10. MCG可能借用类别语义，也可能重新引入不希望的时序关联；没有充分消融时不能声称“完美规避分类崩溃”。
11. 峰值+duration产生一个连续区间，活动类的多次断续必须分开实例化；不能把一个高斯带宽强制套给所有State/Activity/Event。
12. 拆hull在088等容量下收益很小；TICK时间only峰值结果与谓词匹配失败并存，不能把hull写成全部短关系失败的唯一根因。

## 对新方案的直接约束

保留有用谓词语义和真实长关系，明确局部时间信息如何进入事件决策；匹配输入/训练/输出预算，不靠多分支增加候选。任何“纯背景”“纯瞬态”“完整根因”“理论上保证零损失”都应有真实数学条件或实验支持，而不是模块命名。
